# PhoneBridge v0.4 威胁模型与权限限制

- **模型提示注入**：屏幕和聊天内容都视为不可信数据，不接受其中的工具权限变更命令。
- **设备权限**：普通第三方 iPhone App 无权任意跨 App 控制其他 App；本包没有系统权限绕过、没有越狱功能。经 Apple 开发者通道的外部设备驱动只用于受控开发验证。
- **Xcode 批准 ≠ PhoneBridge 审批**：`XcodeMCPDriver` 连接 `xcrun mcpbridge` 时，Xcode 的 Agent 批准只解决「本进程能否使用 Xcode 工具」，不授权任何单次手机操作。改变设备状态的点击、滑动、输入、Home 键默认全部拒绝，只有操作者在启动服务的受控终端显式传入 `--allow-xcode-interactions` 才启用；这不是 MCP 工具，Agent 无法自行开启。发送消息仍然禁用。同账号下可自由执行命令的 Agent 仍能直接调用本机 CLI，真机接入前必须把审批移到 Agent 无法访问的通道。
- **真实发送**：任何现实世界消息发送操作均被禁止；Mock 发送只改变内存状态并强制标注 `simulated: true` / `real_message_sent: false`。
- **审批**：模型可申请批准，但 stdio MCP 工具集与 `CoreAPI.dispatch` 都不暴露批准、拒绝、提案列表或恢复动作。批准仅通过 0600 的 Unix Socket 和操作者 CLI 执行。草稿绑定精确联系人 ID、正文和屏幕 revision；超时或屏幕变化失效；一次性执行。
- **审批通道隔离可强制**：`--approval-token-env` 要求每次审批请求携带操作者终端注入的令牌（不出现在进程命令行），`--approval-uid` 用 OS 对端凭据把请求限定到独立账号；配置的 UID 与服务进程同账号时服务拒绝启动。`--require-approval-isolation` 会在缺少令牌／独立 UID 或缺少持久化台账时直接拒绝启动。`phone_status` 的 `submissions.approval_isolated` 披露当前是否隔离。**未配置这两项时只是 Mock 演示模式**；同 OS 账号下能执行 shell 的 Agent 仍可能自行运行审批 CLI，可写联调与真机阶段必须配置独立 UID 或外部可信审批端。
- **通用交互不得绕过唯一提交入口**：设备接管模式下，Agent 一旦获得点击、滑动或输入能力，就可能直接操作界面上的发送／发布按钮，绕过 `phone_execute_operation` 的逐笔审批。`CoreAPI` 在每次状态改变后回读记录数，通用交互若使记录增加会标记 `submission_bypass_detected` 并暂停。可写交互启用前必须验证：未批准、目标或正文变更、过期、重放、通用交互绕行均无法产生提交结果；无法证明时保持提交路径禁用。审批外置与唯一提交入口是真机可写联调的前置条件，见 [实现计划](implementation-plan.md)。
- **提交状态持久化且脱敏**：`--submission-state` 指定 0700 目录内的 0600 JSONL 台账，只记录操作 ID、收件人 ID、正文 SHA-256 与长度及状态迁移，**不存明文正文**。派发状态在设备调用前以 `fsync` 原子落盘，跨进程用 `flock` 串行化。服务启动时先识别已批准或可能已派发的操作并读回设备：确认已有记录就标记完成且不重发，无法确认则暂停且禁止自动重发。`driver.virtual_send` 只在 `submissions.py` 的提交门被调用。`CoreAPI` 不为任何提交类动作给出自动重试建议。
- **敏感数据**：Mock 审核日志仅保存动作、结果和可公开的虚拟 ID，不记录消息正文。`phone_inspect` 在 Mock 中返回虚拟消息，Apple simctl 截图可能包含真正个人资料，文件只保存在本地 0700 目录中，文件权限为 0600；截图不会自动上传，但未来接入模型须有明确数据处理策略。
- **暴露面**：只提供本机 stdio MCP 和本地 Unix socket；不启动公网 HTTP 服务、不需要云服务器、不在项目中储存模型 API Token。
- **拒绝服务**：单条 MCP 请求限定长度，消息最大 1000 字，操作 ID 仅执行一次。但当前原型仍有内存中的待审批提案累积和日志增长问题，生产环境需要额外配额、回收和速率限制。
- **生产环境**：不得让 Agent 自主登录/操作银行、券商、交易、支付，或在没有权限隔离的情况下执行不可逆外部动作。

启用 `--audit-path` 时，指定已存在的私有目录内的文件路径。服务仅写入当前用户持有的 0600 普通文件。若审计写入失败，返回 `audit_recorded: false` 并保留原始操作结果；以聊天记录回读核验模拟执行结果。
