# PhoneBridge v0.4 威胁模型与权限限制

- **模型提示注入**：屏幕和聊天内容都视为不可信数据，不接受其中的工具权限变更命令。
- **设备权限**：普通第三方 iPhone App 无权任意跨 App 控制其他 App；本包没有系统权限绕过、没有越狱功能。经 Apple 开发者通道的外部设备驱动只用于受控开发验证。
- **Xcode 批准 ≠ PhoneBridge 审批**：`XcodeMCPDriver` 连接 `xcrun mcpbridge` 时，Xcode 的 Agent 批准只解决「本进程能否使用 Xcode 工具」，不授权任何单次手机操作。改变设备状态的点击、滑动、输入、Home 键默认全部拒绝，只有操作者在启动服务的受控终端显式传入 `--allow-xcode-interactions` 才启用；这不是 MCP 工具，Agent 无法自行开启。同账号下可自由执行命令的 Agent 仍能直接调用本机 CLI，真机接入前必须把审批移到 Agent 无法访问的通道。
- **真实发送**：任何现实世界消息发送操作均被禁止；Mock 发送只改变内存状态并强制标注 `simulated: true` / `real_message_sent: false`。自有的合成夹具可以在额外的人工开关下产生一条合成记录，见下条，它与真实发送无关。
- **合成夹具虚拟提交的范围**：`--allow-fixture-virtual-submit` 是操作者在启动服务时显式给出的第二个开关，只允许**唯一提交门**在自有合成夹具内点击一次启用的 Send／Post 控件、生成一条合成记录并返回 `simulated: true` / `real_message_sent: false`。CLI 强制它必须同时满足 `--driver xcode-mcp`、`--allow-xcode-interactions` 与 `--require-approval-isolation`（实际令牌 + 持久化台账）；默认关闭，Agent 无法自行开启。`XcodeMCPDriver.virtual_send` 每次都基于新鲜层级重新校验前台夹具、目标联系人与草稿正文，并回读确认记录刚好增加一条且文本匹配，否则返回失败并暂停。夹具按 G1 基线以 `pb-disable-submit` 启动时该开关也不生效（`submit_control_unavailable`）。不打开真实第三方 App、不接触真实设备、不发真实消息；此能力只用于 G2 验收，不构成真实发送授权。 [实现计划](implementation-plan.md)
- **审批**：模型可申请批准，但 stdio MCP 工具集与 `CoreAPI.dispatch` 都不暴露批准、拒绝、提案列表或恢复动作。批准仅通过 0600 的 Unix Socket 和操作者 CLI 执行。草稿绑定精确联系人 ID、正文和屏幕 revision；超时或屏幕变化失效；一次性执行。
- **审批通道隔离**：外部托管模式要求真实令牌、不同的服务与审批 UID、独立的 0700 空审批目录。套接字是目录内唯一的服务资产。macOS ACL 为具名审批账号授予目录访问和条目增删、套接字读写权限。台账、审计和 MCP 套接字必须留在服务账号专用目录。启动失败及正常关闭会回收目录授权。审批客户端发送令牌前核对已连接的服务 UID，服务逐连接校验审批 UID 与令牌。未启用托管模式的同账号令牌仅用于受控演示。服务账号本身仍需要受控，任意同账号 shell 可访问服务文件。旧部署迁移见 [README](../README.md)。
- **通用交互不得绕过唯一提交入口**：设备接管模式下，Agent 一旦获得点击、滑动或输入能力，就可能直接操作界面上的发送／发布按钮，绕过 `phone_execute_operation` 的逐笔审批。`XcodeMCPDriver` 在每次交互前的新鲜层级里定位启用的提交控件，通用点击／滑动命中即在**派发交互命令之前**返回 `submission_requires_approval`；无法定位启用控件时 fail closed。`CoreAPI` 另在状态改变后按当次观察回读记录数，若记录增加会标记 `submission_bypass_detected` 并进入持久暂停。安全类拒绝不返回重试建议。G2 的完整可写验收已在 Apple Simulator 上实测通过：未批准、目标或正文变更、屏幕变化失效、重放、通用交互绕行均无法产生提交结果，批准后只新增一条可归属的匹配记录；证据见 [测试报告](test-report.md)。仍不开放真实设备与真实第三方 App。见 [实现计划](implementation-plan.md)。
- **提交状态持久化且脱敏**：台账保存操作 ID、目标、正文摘要、长度、派发前记录基线和状态迁移。派发状态先落盘，跨进程以文件锁串行化。结果未决的操作会在每次启动时恢复为写入暂停，只读放行。可信审批终端用 `approvals reconcile <操作 ID>` 发起当次回读。对已派发的 Simulator 操作，必须在目标会话中看到基线加一且正文摘要匹配，或确认记录数仍等于基线。记录不足、增加多条或正文不匹配时保持暂停。已核对的操作以终态落盘且禁止重发。非提交类回读暂停保留在当前后端任务中。 [恢复流程](../README.md)
- **敏感数据**：Mock 审核日志仅保存动作、结果和可公开的虚拟 ID，不记录消息正文。`phone_inspect` 在 Mock 中返回虚拟消息，Apple simctl 截图可能包含真正个人资料，文件只保存在本地 0700 目录中，文件权限为 0600；截图不会自动上传，但未来接入模型须有明确数据处理策略。
- **暴露面**：只提供本机 stdio MCP 和本地 Unix socket；不启动公网 HTTP 服务、不需要云服务器、不在项目中储存模型 API Token。
- **可重连 relay 与客户端环境**：`backend --socket` 只在私有路径创建 0600 Unix 套接字，不监听 TCP、不开放公网；relay 仅转发 MCP JSON 行，每次连接重建协议会话，服务状态与审批台账留在后端进程。`phonebridge/hark.py` 构造客户端命令时把审批令牌从客户端环境移除，令牌不出现在命令行；`scripts/hark-codex-spike.py` 逐阶段校验这一点。relay 与 SSH 回环脚本只验证主机侧传输，不构成 Hark 客户端或真实模型编排的验收，也不改变「真实发送禁用」「同账号下令牌非强隔离」等既有边界。
- **现场跨 UID 验收**：`scripts/cross-uid-approval-spike.py` 以真实审批 UID 运行客户端并核对 OS 对端凭据；令牌从具名可读文件加载，不进入子命令。`--authenticate` 只启动一次交互式 `sudo -u <approver>` 常驻代理，控制 socket 由服务账号创建并仅对该具名 UID 加 `read,write` ACL，后续请求经 socket 往返、不依赖 sudo 票据共享；密码由 sudo 直接向终端提示，脚本不读取、不存储、不转发。默认 `sudo -n` 模式不可用时输出 `outcome: blocked` 与带仓库绝对路径的现场命令；以 root 运行脚本本体时被 `script_must_not_run_as_root` 拒绝，避免服务侧变成 root 而改变两个非特权账号分离的验收语义。脚本不做提权绕过，也不把注入替身的彩排结果记为真实进程验收。**现场结果（2026-11-11）**：`outcome: "passed"`、`cross_uid_process_verified: true`、`approver_process_real: true`、`real_model_calls: false`，15 项判据全过，详见 [测试报告](test-report.md)。保存结果可用 `--verify-evidence <PATH>` 只读复核结构完整性（彩排、缺项、假值、计数或响应篡改一律 `evidence_verified: false`），该复核不启动进程、不能证明文件来源；原始输出含本机 UID 与绝对路径，不入库。验收限于 macOS 本机两个非特权账号之间的外部托管端点，不覆盖真机、独立审批设备、真实第三方 App、Hark 客户端端到端、真实模型编排或真实 App Intents，真实发送仍禁用。
- **通道 A 意图边界**：仅 Mock 公布合成只读意图，聊天回读绑定已选的合成联系人。未公布的能力只返回 B 路由建议，写意图拒绝执行。结果不明时暂停当前后端写动作并阻止重试，须由可信侧回读后恢复。真实 App Intents 和快捷指令另行验收。
- **远程只读 MCP**：`phonebridge.remote_readonly` 是另一个进程，只绑定 `127.0.0.1`，驱动固定为 Mock，不接受 `--driver`，也不连接主后端套接字。工具只有 `phone_status`、`intent_run`、`phone_inspect`，`intent_run` 只允许 `contacts.lookup`。令牌从环境变量读入后立刻换成 HMAC，请求只认 `Authorization: Bearer`，URL 参数里的令牌拒绝。鉴权失败对外是同一个 401，原因只进不含令牌的审计。带 `Origin` 的请求必须指向本进程的回环地址。公网隧道和 Hark 注册不在这一步，开启前要单独评审。
- **拒绝服务**：单条 MCP 请求限定长度，消息最大 1000 字，操作 ID 仅执行一次。但当前原型仍有内存中的待审批提案累积和日志增长问题，生产环境需要额外配额、回收和速率限制。
- **生产环境**：不得让 Agent 自主登录/操作银行、券商、交易、支付，或在没有权限隔离的情况下执行不可逆外部动作。

启用 `--audit-path` 时，指定已存在的私有目录内的文件路径。服务仅写入当前用户持有的 0600 普通文件。若审计写入失败，返回 `audit_recorded: false` 并保留原始操作结果；以聊天记录回读核验模拟执行结果。
