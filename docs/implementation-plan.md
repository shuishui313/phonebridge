# PhoneBridge 实现思路与步骤

2026-11-10 沉淀。本文把产品目标、架构决策、技术实现方式、两套边界方案和排期步骤集中到一处，供后续接手者直接执行。文中「我们」若未特别说明，**指最终理想态，不是当前已完成能力**；当前证据一律以 [测试报告](test-report.md) 为准。

本文不记录任何同类社区项目的名称，调研结论只做匿名化表述；社区方案声明的能力均未经本仓库独立复现，不作为验证证据。[产品需求](product-requirements.md) · [阶段验收](acceptance.md) · [iOS 可行性](ios-feasibility.md) · [安全边界](security.md)

## 一、目标态与硬约束

最终产品是「统一手机操作能力 + 两种产品形态」：外部 Agent App 通过 MCP 接入，或用户直接使用独立 App；两者共享同一核心。用户在 Hark 之类的入口说一句话，Agent 就能在授权范围内观察、操作、验证 iPhone 任务。

硬约束：

1. 首期只做 iPhone，不扩展 Android。
2. 真实设备、真实第三方 App 只在用户另行授权后验证；不使用真实账号或个人数据。
3. 不越狱、不绕过系统安全保护；普通 App 跨 App 控制若平台不允许，就明确写成边界，不用模拟结果冒充。
4. 发送消息等敏感动作必须由独立于 Agent 权限的通道审批，不能只靠提示词。
5. 核心不绑定任何特定 Agent；接入壳要薄。
6. 最终希望只在 iPhone 本机运行，但允许先经电脑验证；Mac 侧成果不计入本机运行完成度。

## 二、架构决策

| 决策 | 理由 | 代价 | 回退 |
| --- | --- | --- | --- |
| 一个核心、两个壳 | 接入形态（MCP）与独立形态（App 对话 UI）复用任务引擎，避免逻辑分裂 | 核心必须先稳定为内部 API | 核心 API 未稳定前不启动独立 App |
| 核心与 Agent 完全解耦 | 防止为某个 Agent 写死逻辑，后续无法换模型或换入口 | 协议适配层要额外维护 | 适配器只做协议转换 |
| 双通道路由，A 优先 B 兜底 | 意图通道依赖公开接口；设备接管受界面变化影响 | 需要能力清单与路由判定 | A 缺少能力，或失败且确认无副作用时，才走 B。任何通道结果不明时先回读，无法确认就暂停 |
| 驱动抽象保持鸭子类型契约 | 现有 Mock / simctl / 官方驱动可并行演进，测试可注入替身 | 缺少编译期接口约束 | 用统一契约测试覆盖每个驱动 |
| 官方设备能力只做白名单适配 | 开发工具与设备操作混杂，全量接入会改变项目性质 | 官方能力升级时需同步白名单 | 只映射设备交互与诊断工具 |
| 审批与 Agent 权限隔离 | 逐操作绑定设备、App、目标、正文和有效期；批准只可消费一次 | 需要独立账号或外部可信审批端 | 同一账号的 CLI 仅用于 Mock 演示。Simulator 可写联调前验证 Agent 无法自批或绕过提交入口 |
| 验证使用业务状态与界面证据 | 联系人 ID、草稿正文和记录增量可说明动作结果；截图哈希辅助诊断 | 需要新鲜状态和可定位的测试夹具 | 缺少本次状态或结果不明时先回读，仍不明就暂停 |
| 状态持久化与操作 ID 去重 | 断线、重启、重连后防止危险动作重复执行 | 需要存储与恢复逻辑 | 先持久化最小任务状态，不做完整历史库 |
| 传输层独立于核心 | 本机 stdio 面向 Codex/Hark，远程 HTTPS MCP 面向云端客户端 | 需鉴权与最小 scope | 远程适配器后置，不改核心 |

## 三、分层与技术选型

```text
外部 Agent（Hark 经 SSH 启动 Codex）       独立 App 用户
     │ 本机 stdio / 后续远程 HTTPS MCP          │ App 内对话 UI
     ▼                                         ▼
┌──────────────────────────────────────────────────────────┐
│ 核心：任务引擎 · 路由 · 审批 · 策略 · 验证 · 审计 · 状态   │
└──────────────────────────────────────────────────────────┘
     │
     ▼
通道 A：App Intents / 快捷指令（显式公开动作）
通道 B：设备接管（截图 + UI 层级 + 合成事件）
     │
     ▼
驱动：Mock / simctl / Xcode MCP / 未来真机
```

| 层 | 当前实现 | 目标技术 | 约束 |
| --- | --- | --- | --- |
| 核心 | Python 标准库，`PhoneBridge` 状态机、提案 TTL、RLock、JSONL 审计 | 抽出稳定内部 API；任务时限、动作预算、有限重试、断线恢复、持久化最小状态 | 不引入必须联网的依赖；核心可独立测试 |
| MCP 接入 | 12 个 stdio 工具，自研 JSON-RPC host | 增加远程 HTTPS 传输适配器 + 令牌鉴权 + 会话 scope | 远程不绕过审批；不默认开放公网 |
| 独立 App | 未启动 | 首个 Swift 原型可通过受控接口使用 Mac 上的 Python 核心，验证对话和模型配置 | 核心 API 稳定且 G2 通过后再启动。iPhone 端侧运行由 G4 单独验收 |
| 通道 A | 未实现 | App Intents / 快捷指令；Mac 侧可用 `shortcuts run` 触发；逐项验证可用参数、用户交互、结果回读 | 只能做被显式公开的动作；目标 App 是否公开需实测 |
| 通道 B | `XcodeMCPDriver` 已接入 `xcrun mcpbridge`，支持白名单工具、界面层级和坐标交互 | 先补齐 Simulator 与前台夹具校验，再评估 Apple 支持的真机授权通道 | 真机目标、可用动作和设备配置须逐项取证 |
| 审批 | Mock 使用 0600 Unix 套接字与 CLI；Xcode 驱动有启动开关 | 用独立 UID 或外部可信审批端逐操作绑定，唯一提交入口负责核验和消费审批 | 启动开关用于开发。可写联调前须验证无法通过通用点击、键盘或其他工具提交 |
| 验证 | Mock 回读合成记录；Xcode 交互可返回本地截图与界面层级路径 | 回读稳定标识、精确草稿和记录增量；截图哈希辅助诊断 | 只将本次观察视为当前状态。提交结果不明时禁止自动重放 |
| 状态 | 进程内内存，重启清空 | 持久化操作 ID、审批有效性、任务状态与核验结论（SQLite 或私有 JSONL） | 日志脱敏，不记消息正文 |
| 设备测试资产 | SwiftUI 合成夹具（私信 / 信息流两个场景）、3 项 XCUITest、XcodeGen、两条 CI | 继续作为固定回归证据，不因运行时驱动切换而删除 | 真实 App 与真机另行授权 |
| 安全 | Mock 限于合成数据，Xcode 通用交互默认关闭 | 校验设备与前台夹具，阻断非授权操作；后续补会话 scope 和敏感内容保护 | 银行、券商和支付默认禁用。依据 [安全边界](security.md) |

## 四、两套边界方案

### 4.1 最小试错方案（步骤 0a、0b）

目标是在隔离的 iPhone Simulator 上验证 `Codex → PhoneBridge MCP → Xcode 驱动 → 自有夹具` 的拟稿和回读。使用已有 Xcode、驱动与合成测试数据，提交按钮在此次试跑中禁用。逐笔审批和实际提交留给步骤 2 验收。

1. **0a · 驱动准入。** 启动前核对目标在 Simulator 清单中，并核验会话返回的设备类型。观察与交互限定在自有夹具；每次交互前确认目标和前台 App。为握手、调用、退出设置超时，断线后释放失效进程和会话。缺失本次截图或层级时返回明确错误，不把缓存当作当前状态。用替身覆盖非 Simulator、前台变化、桥接无响应或断开、旧状态四类反例。通过后才允许 Agent 开启拟稿交互。
2. **0b · 拟稿与回读。** 在隔离开发会话启动 `--driver xcode-mcp --sim-udid <UDID>`。仅当夹具已禁用发送和发布时，由操作者用 `--allow-xcode-interactions` 重启该会话。让 Codex 打开合成私信、定位 Casey（`contact-02`）、输入「测试消息」并回读。`phone_inspect` 返回本地文件路径，由同一台 Mac 上的 Codex 读取本次层级。核对联系人稳定 ID、完整草稿和记录增量为零，截图哈希用于辅助排查。
3. **确认负面用例与记录结果。** 省略交互开关时，`phone_tap` 应被拒绝；当前驱动的 `message_prepare` 仍应拒绝提交请求。这两项分别记录为开关和驱动能力边界。保存环境版本、调用序列、核验结论和失败原因，截图与层级文件留在本地。

先区分 Xcode 授权、握手、设备状态或观察失败与界面定位不稳。前置条件通过后，若同一拟稿场景仍无法稳定回读，就继续用 simctl 和固定 XCUITest 保留回归，并将通道 B 保持在实验阶段。通道 A 的公开能力调查可并行推进。

### 4.2 最大可能实现方案（技术上限，非承诺）

| 能力 | 判断 | 依据与条件 |
| --- | --- | --- |
| 真机只读观察、自有 App 操作 | 待实测 | 用户分别授权只读和写入，再逐项验证 Apple 支持的能力 |
| 真机操作目标第三方 App | 待实测 | 社区公开声明仅供确定研究方向。需逐 App、逐能力核实 |
| 意图通道完成系统动作（如发送信息） | 有条件可实现 | 取决于系统/目标 App 是否公开对应动作；未验证前不列入能力清单 |
| 独立审批外置、逐操作绑定 | 可实现 | 工程问题，真机前必须完成 |
| 双形态共享核心、远程 MCP | 可实现 | 核心 API 稳定 + 鉴权与 scope |
| 状态持久化、断线恢复、防重 | 可实现 | 工程问题，需在真机前完成 |
| 只在 iPhone 本机运行 | 待验证 | 社区方案声明存在本机回环架构；需单独立项验证 Apple 允许的安装与运行方式 |
| 普通 App Store 应用跨 App 控制任意 App | 目前判断不可行 | 沙箱限制；除非 Apple 明确开放能力，不绕过系统保护 |
| 自动化第三方 App 的合规性 | 风险由用户判断 | 可能违反服务条款，文档须明确披露 |

组成：核心 + 双壳 + 双通道 + 三到四类驱动 + 外置审批 + 任务引擎 + 双证据验证 + 持久化 + 远程传输。任一「有条件/待验证」项未通过验收，就停在对应门槛，不向后传递。

### 4.3 差距与决策门

| 门 | 判据 | 通过 | 不通过 |
| --- | --- | --- | --- |
| G1 Simulator 拟稿 | 步骤 0a、0b 通过，固定联系人与草稿可稳定回读，提交增量为零；默认交互被拒绝、提交路径禁用两处负面用例均生效 | 继续核心稳定化和审批测试。Hark 可并行用 Mock 验证连接 | 按失败原因修复或保留实验性，固定 XCUITest 继续回归 |
| G2 审批与 Hark 联调 | 先通过步骤 1、2 的审批与恢复测试，再完成步骤 3 的 Hark 读写与重连验收 | 可开始主机托管的 Swift 原型和远程接入评估 | 保持在受控的 Mock 或 Simulator 范围 |
| G3a 真机只读 | 用户明确授权只读，确定指定设备、自有 App 和只读范围 | 仅执行只读测试，收集证据 | 保持 Simulator 阶段 |
| G3b 真机受控写入 | G2 通过，真机只读证据齐备，审批已外置，用户另行授权指定写动作 | 从自有 App 的受控写入开始。真实第三方 App 另按目标和能力申请授权 | 保持只读 |
| G4 iPhone 本机运行 | 先判定端侧核心的运行形态（Python 核心不能直接迁移到 iOS，需评估 Swift 重写或仅保留意图通道），再在 Apple 支持的安装和运行方式下实测端侧核心、授权能力和审批 | 进入本机形态产品化 | 继续主机托管形态；终态仍以 iPhone 本机独立运行为目标 |

## 五、实施步骤

本文步骤编号仅用于排期，与 [阶段验收](acceptance.md) 的 A–E 和 HANDOFF 的历史 P0–P4 独立。

| 步骤 | 任务 | 产出 | 验收判据 | 依赖 | 风险 / 回退 |
| --- | --- | --- | --- | --- | --- |
| 0a · 驱动准入 | 按 4.1 核验 Simulator、夹具、桥接超时和状态新鲜度。当前 `XcodeMCPDriver` 尚无设备类型、前台夹具、调用超时与状态新鲜度校验，本步骤含源码修改 | 驱动修复与反例测试 | 非 Simulator、夹具变化、超时或旧状态均无法继续交互 | Mock 与现有 CI | 失败时使用 Mock 或已验证的 Simulator 只读路径 |
| 0b · 拟稿试跑 | 在自有夹具停用提交，跑通 Codex 拟稿与回读 | 调用序列与核验记录 | 稳定联系人 ID、精确正文、记录增量为零 | 步骤 0a | 按 4.1 区分环境与界面问题 |
| 1 · 核心稳定化 | 稳定内部 API，补任务时限、动作预算与有限重试 | 核心 API 和测试 | 超时、预算耗尽、只读重试上限、结果不明的回读路径均有测试 | G1 | 保持现有 MCP 工具契约 |
| 2 · 逐笔审批与恢复 | 将审批放到 Agent 无法使用的通道；提供唯一提交入口，执行前原子记录操作 ID、审批消费和派发状态 | 审批通道、最小状态存储、故障测试 | 拒绝未批准、目标或正文变更、过期、重放及通用交互绕行。批准后只增加一条匹配记录。并发或重启后不会重复提交 | 步骤 1 | 状态不存明文正文。回执丢失先按目标与操作 ID 核验，仍不明就暂停 |
| 3 · Hark 联调 | Hark 经 SSH 进入运行 Codex 的主机，由 Codex 调用 PhoneBridge | 连通、成功、失败、中断记录 | Mock 连接可提前试跑。完整合成任务须在 Hark 回读结果，并验证重连不会重复提交 | 完整验收依赖步骤 2 | SSH 不稳定时单列连接问题 |
| 4 · 通道 A | 并行调查公开动作，用只读动作或自有 App 合成意图验证 | 能力清单、路由测试 | 逐项记录参数、用户交互、结果回读。真实发送等写动作需另行授权 | 能力调查可立即开始，统一路由依赖步骤 1 | 目标 App 未公开的动作不列入可用清单 |
| 5 · 主机托管的 Swift 原型 | Swift 对话界面调用 Mac 上的核心 API | 可运行的 Swift 对话原型 | 与 MCP 形态共享主机侧审批、验证和审计 | G2 和稳定的核心 API | iPhone 本机运行单列 G4 |
| 6 · 远程 MCP | HTTPS 适配器、身份认证与最小会话权限 | 适配器与权限测试 | 未授权权限被拒绝，远程请求遵守同一审批边界 | G2 和稳定的核心 API | 默认不开放公网 |
| 7 · 真机阶段 | 分开验收只读、自有 App 受控写入、目标第三方 App 和本机运行 | 真机报告与能力清单 | 每一步按已授权的设备、App 和能力逐项记录 | 只读依赖 G3a，写入依赖 G3b，本机形态依赖 G4 | 任一能力未实测就保持待验证，金融操作默认禁用 |

步骤 2 的回归须分别模拟提交前中断、提交后回执丢失。恢复时先识别已批准或可能已派发的操作，读回结果再决定状态。对可能已经提交且无法确认结果的操作，禁止自动重发。

## 六、安全与验收底线

- 任何阶段都不得把 Mock 或 Simulator 结果描述为真机能力。
- 发送消息、执行外部交易、删除数据须逐操作审批；审批绑定目标与内容、短时有效、单次执行。
- 银行、券商、支付应用默认禁用；测试只用合成联系人与消息；截图与层级默认留在本地。
- 每个可验证增量完成后，及时将相关源码、测试和说明提交并推送到 GitHub。交付记录包含分支、commit SHA、测试命令与结果、已验证和待验证的能力、已知问题及下一步。
- 文档不记录同类社区项目名称；调研结论匿名化沉淀。
- 遇到 Xcode、GitHub 权限或设备访问等环境限制时，完成不依赖该条件的工程工作并明确记录阻碍。
