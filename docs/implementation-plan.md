# PhoneBridge 实现思路与步骤

2026-11-10 沉淀。本文把产品目标、架构决策、技术实现方式、两套边界方案和排期步骤集中到一处，供后续接手者直接执行。文中「我们」若未特别说明，**指最终理想态，不是当前已完成能力**；当前证据一律以 [测试报告](test-report.md) 为准。

本文不记录任何同类社区项目的名称，调研结论只做匿名化表述；社区方案声明的能力均未经本仓库独立复现，不作为验证证据。[产品需求](product-requirements.md) · [阶段验收](acceptance.md) · [iOS 可行性](ios-feasibility.md) · [安全边界](security.md)

## 一、目标态与硬约束

最终产品是「统一手机操作能力 + 两种产品形态」：外部 Agent App 通过 MCP 接入，或用户直接使用独立 App；两者共享同一核心。用户在 Hark 之类的入口说一句话，Agent 就能在授权范围内观察、操作、验证 iPhone 任务。

硬约束：

1. 首期只做 iPhone，不扩展 Android。
2. 真实设备、真实第三方 App 只在用户另行授权后验证；不使用真实账号或个人数据。
3. 不越狱、不绕过系统安全保护；普通 App 跨 App 控制若平台不允许，就明确写成边界，不用模拟结果冒充。
4. 发送消息等敏感动作必须由独立于 Agent 权限的通道审批，不能只靠提示词。
5. 核心不绑定任何特定 Agent；接入壳要薄。
6. 最终希望只在 iPhone 本机运行，但允许先经电脑验证；Mac 侧成果不计入本机运行完成度。

## 二、架构决策

| 决策 | 理由 | 代价 | 回退 |
| --- | --- | --- | --- |
| 一个核心、两个壳 | 接入形态（MCP）与独立形态（App 对话 UI）复用任务引擎，避免逻辑分裂 | 核心必须先稳定为内部 API | 核心 API 未稳定前不启动独立 App |
| 核心与 Agent 完全解耦 | 防止为某个 Agent 写死逻辑，后续无法换模型或换入口 | 协议适配层要额外维护 | 适配器只做协议转换 |
| 双通道路由，A 优先 B 兜底 | 意图通道稳定、快、不怕 UI 改版；设备接管通用但脆弱 | 需要能力清单与路由判定 | A 不可用时才走 B；B 失败先回读再决定是否重试 |
| 驱动抽象保持鸭子类型契约 | 现有 Mock / simctl / 官方驱动可并行演进，测试可注入替身 | 缺少编译期接口约束 | 用统一契约测试覆盖每个驱动 |
| 官方设备能力只做白名单适配 | 开发工具与设备操作混杂，全量接入会改变项目性质 | 官方能力升级时需同步白名单 | 只映射设备交互与诊断工具 |
| 审批层独立于 MCP 工具集 | Agent 无法自批；逐操作绑定目标、内容、有效期、单次执行 | 需额外可信终端或外部设备 | 真机前把审批移到 Agent 不可访问的通道 |
| 验证层用双证据 | 单次截图不足以判定动作生效；层级 + 截图哈希可交叉核对 | 多一次观察调用 | 结果不明时先回读，仍不明就暂停 |
| 状态持久化与操作 ID 去重 | 断线、重启、重连后防止危险动作重复执行 | 需要存储与恢复逻辑 | 先持久化最小任务状态，不做完整历史库 |
| 传输层独立于核心 | 本机 stdio 面向 Codex/Hark，远程 HTTPS MCP 面向云端客户端 | 需鉴权与最小 scope | 远程适配器后置，不改核心 |

## 三、分层与技术选型

```text
外部 Agent App（Hark / ChatGPT / 其他）      独立 App 用户
     │ MCP stdio（本机） / HTTPS（远程）          │ App 内对话 UI
     ▼                                            ▼
┌──────────────────────────────────────────────────────────┐
│ 核心：任务引擎 · 路由 · 审批 · 策略 · 验证 · 审计 · 状态   │
└──────────────────────────────────────────────────────────┘
     │
     ▼
通道 A：App Intents / 快捷指令（显式公开动作）
通道 B：设备接管（截图 + UI 层级 + 合成事件）
     │
     ▼
驱动：Mock / simctl / Xcode MCP / 未来真机
```

| 层 | 当前实现 | 目标技术 | 约束 |
| --- | --- | --- | --- |
| 核心 | Python 标准库，`PhoneBridge` 状态机、提案 TTL、RLock、JSONL 审计 | 抽出稳定内部 API；任务时限、动作预算、有限重试、断线恢复、持久化最小状态 | 不引入必须联网的依赖；核心可独立测试 |
| MCP 接入 | 12 个 stdio 工具，自研 JSON-RPC host | 增加远程 HTTPS 传输适配器 + 令牌鉴权 + 会话 scope | 远程不绕过审批；不默认开放公网 |
| 独立 App | 未启动 | Swift App 复用核心 API；自带模型配置（兼容端点），对话 UI 只做壳 | 核心 API 稳定后再启动 |
| 通道 A | 未实现 | App Intents / 快捷指令；Mac 侧可用 `shortcuts run` 触发；逐项验证可用参数、用户交互、结果回读 | 只能做被显式公开的动作；目标 App 是否公开需实测 |
| 通道 B | `XcodeMCPDriver`：`xcrun mcpbridge`，6 工具白名单，官方交互命令语法，层级换算归一化坐标 | 真机授权通道（iOS 27+ 官方同源协议优先，旧系统自签 Helper 作为回退研究） | 无越狱；USB 信任、开发者模式、自签有效期、App 环境检测列为验收项 |
| 审批 | Unix 域套接字 + 独立 CLI；0600 权限 | 真机阶段改为独立 UID 或外部可信审批设备；逐操作绑定 | 当前配置只适用于受控模拟 |
| 验证 | 操作前后状态比对；截图 SHA-256；UI 层级 | 双证据（层级元素 + 截图哈希），必要时 OCR 兜底；活动记录可回放 | 结果不明先回读，不盲重试 |
| 状态 | 进程内内存，重启清空 | 持久化操作 ID、审批有效性、任务状态与核验结论（SQLite 或私有 JSONL） | 日志脱敏，不记消息正文 |
| 设备测试资产 | SwiftUI 合成夹具（私信 / 信息流两个场景）、3 项 XCUITest、XcodeGen、两条 CI | 继续作为固定回归证据，不因运行时驱动切换而删除 | 真实 App 与真机另行授权 |
| 安全 | 金融/支付默认禁用、真实发送禁用、交互需人工显式开启 | 首次 Agent 连接授权、会话最小 scope、敏感 App 隐藏、验证码遮蔽 | 依据 [安全边界](security.md) |

## 四、两套边界方案

### 4.1 最小试错方案（先证伪，再投入）

**唯一目标**：用最低成本证明「自然语言 → Agent → PhoneBridge MCP → 官方设备驱动 → 合成夹具 → 独立审批 → 回读验证」这条链能闭环，且审批不可绕过。不接真机、不做本机运行、不做独立 App、不新增依赖。

前提全部已具备：完整 Xcode、已启动的 iPhone Simulator、已安装的合成夹具、`XcodeMCPDriver`、12 个 MCP 工具、CI 回归。

步骤：

1. 在开发用 Codex 会话注册 `--driver xcode-mcp --sim-udid <UDID>`，另开受控终端显式追加 `--allow-xcode-interactions`。
2. 下达自然语言任务：「打开合成私信场景，找到 Casey，输入『测试消息』，不要发送」。
3. 观察：`phone_status` 与 `phone_inspect` 返回截图、UI 层级、元素 hitPoint；按层级换算 0–1 坐标，依次 `phone_tap` 聚焦输入区、`phone_type_text` 录入。
4. 验证：`phone_inspect` 回读草稿与界面文本，比对操作前后截图 SHA-256 与层级变化。
5. 反向验证：不带交互开关启动时 `phone_tap` 必须返回 `independent_approval_required`；`message_prepare` 在真实驱动上必须返回 `real_message_sending_disabled`。
6. 记录证据：环境版本、命令、工具调用序列、截图哈希、失败原因、未验证项。

验收：闭环成功且两处拒绝生效。**证伪条件**：若 Codex 无法稳定按层级坐标完成多步操作，说明通用 UI 接管在当前阶段不可靠，应把重心转向通道 A 与自有 App 的显式接口，而不是继续堆驱动。成本：零新依赖、零新设备、主要改动是配置与文档。回退：simctl 驱动 + 固定 XCUITest 保持回归能力不受影响。

### 4.2 最大可能实现方案（技术上限，非承诺）

| 能力 | 判断 | 依据与条件 |
| --- | --- | --- |
| 真机只读观察、自有 App 操作 | 可实现 | 用户授权 + Apple 支持的开发者机制；先只读后受控交互 |
| 真机操作目标第三方 App | 有条件可实现 | 社区公开方案声明无越狱可行；需逐 App、逐能力实测，受 TOS 与环境检测影响 |
| 意图通道完成系统动作（如发送信息） | 有条件可实现 | 取决于系统/目标 App 是否公开对应动作；未验证前不列入能力清单 |
| 独立审批外置、逐操作绑定 | 可实现 | 工程问题，真机前必须完成 |
| 双形态共享核心、远程 MCP | 可实现 | 核心 API 稳定 + 鉴权与 scope |
| 状态持久化、断线恢复、防重 | 可实现 | 工程问题，需在真机前完成 |
| 只在 iPhone 本机运行 | 待验证 | 社区方案声明存在本机回环架构；需单独立项验证 Apple 允许的安装与运行方式 |
| 普通 App Store 应用跨 App 控制任意 App | 目前判断不可行 | 沙箱限制；除非 Apple 明确开放能力，不绕过系统保护 |
| 自动化第三方 App 的合规性 | 风险由用户判断 | 可能违反服务条款，文档须明确披露 |

组成：核心 + 双壳 + 双通道 + 三到四类驱动 + 外置审批 + 任务引擎 + 双证据验证 + 持久化 + 远程传输。任一「有条件/待验证」项未通过验收，就停在对应门槛，不向后传递。

### 4.3 差距与决策门

| 门 | 判据 | 通过 | 不通过 |
| --- | --- | --- | --- |
| G1 最小试错 | Simulator 端到端闭环 + 两处拒绝生效 | 继续通道 B，进入 Hark 联调 | 转通道 A 优先，通道 B 降为实验性 |
| G2 Agent 联调 | Hark 经 SSH 触发 Codex 完成任务并回读结果，断线不重复执行 | 进入任务引擎与独立 App 骨架 | 补超时、预算、恢复，暂不接真机 |
| G3 真机授权 | 用户明确授权 + 审批已外置 + 只读证据齐备 | 真机从自有 App 只读起步，再受控交互 | 保持 Simulator 阶段 |
| G4 本机运行 | Apple 支持的安装与运行方式实测通过 | 进入独立 App 产品化 | 明确写为平台边界，保留 Mac 侧形态 |

## 五、实施步骤

本文步骤编号仅用于排期，与 [阶段验收](acceptance.md) 的 A–E 和 HANDOFF 的历史 P0–P4 独立。

| 步骤 | 任务 | 产出 | 验收判据 | 依赖 | 风险 / 回退 |
| --- | --- | --- | --- | --- | --- |
| 0 · 最小试错 | 按 4.1 在开发 Codex 会话跑通闭环 | 工具调用序列、截图哈希、拒绝验证记录 | 闭环成功且两处拒绝生效 | 现有环境 | 失败转通道 A / simctl 回退 |
| 1 · 核心稳定化 | 抽出核心内部 API，补任务时限、动作预算、有限重试、结果不明先回读 | 核心 API、单元测试 | 新增测试覆盖超时、预算耗尽、重试上限、回读路径 | 步骤 0 | 不改 12 工具契约，避免破坏回归 |
| 2 · 状态与恢复 | 持久化最小任务状态、操作 ID、审批有效性、核验结论 | 私有状态存储、恢复测试 | 重启后同一操作 ID 不重复执行；审批失效重新请求确认 | 步骤 1 | 日志脱敏，不记正文 |
| 3 · Hark 联调 | Hark → SSH → Codex → PhoneBridge 完成合成任务 | 成功/失败/中断三类记录 | 断线重连不重复执行；结果可回读 | 步骤 1、2 | SSH 不稳定时先记录阻碍，不伪造结果 |
| 4 · 通道 A | 验证系统「发送信息」等显式公开动作；建立能力清单与路由判定 | 能力清单、路由测试 | 逐项记录可用参数、用户交互、结果回读；未验证项不进入清单 | 步骤 1 | 目标 App 未公开动作时明确写为不可用 |
| 5 · 独立 App 骨架 | Swift App 复用核心 API，自带对话与模型配置 | 可运行的最小独立形态 | 与 MCP 接入形态共用审批、验证、审计，结果一致 | 步骤 1、2 | 核心 API 不稳定则顺延 |
| 6 · 远程 MCP | HTTPS 传输适配器 + 令牌鉴权 + 会话最小 scope | 适配器、鉴权测试 | 远程调用不绕过审批，未授权 scope 拒绝 | 步骤 1、2 | 不默认开放公网 |
| 7 · 真机阶段（另行授权） | 只读观察 → 自有 App 受控交互 → 目标 App 逐能力验收 → 本机运行单独立项 | 真机报告、能力边界清单 | 每步记录设备、系统、安装方式、有效期、结果；金融默认禁用 | G3 通过 + 审批外置 | 任一能力未实测不标记为完成；不越狱 |

## 六、安全与验收底线

- 任何阶段都不得把 Mock 或 Simulator 结果描述为真机能力。
- 发送消息、执行外部交易、删除数据须逐操作审批；审批绑定目标与内容、短时有效、单次执行。
- 银行、券商、支付应用默认禁用；测试只用合成联系人与消息；截图与层级默认留在本地。
- 每次交付包含分支、commit SHA、测试命令与结果、已验证能力、未验证能力、已知问题、下一步。
- 文档不记录同类社区项目名称；调研结论匿名化沉淀。
- 遇到 Xcode、GitHub 权限或设备访问等环境限制时，完成不依赖该条件的工程工作并明确记录阻碍。
