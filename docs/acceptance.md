# 产品目标与分阶段验收

用户希望在 Hark 用一句自然语言指令完成 iPhone 上的受控任务。首期以 iPhone 和 iOS 27 为目标设备，以 Codex 作为主要开发与 Agent 工具入口。测试目标 App 定为 WhatsApp 与 X 的交互形态：在自有合成夹具中完成私信（唯一定位测试联系人、拟稿、独立批准、执行一次、回读验证）与信息流（撰写、发布、回读）。不安装或操作真实第三方 App，不使用真实账号；真实 App 验证需用户另行授权。日常开发由 Codex 执行，用户保留发送审批和真机测试决定。

PhoneBridge 使用原创实现与可替换的执行器。Codex 及其他 stdio MCP 客户端可作为 Agent，DeepSeek API 为可选上层模型。长期目标是减少对常驻电脑或云主机的依赖，具体部署取决于 iOS 与目标 App 提供的能力。[架构](architecture.md) · [iOS 可行性](ios-feasibility.md)

| 阶段 | 验收判据 |
| --- | --- |
| A · Python Mock | 启动 MCP 子进程，发现工具，用固定测试联系人完成拟稿。审批前记录增量为零。独立 CLI 批准后执行并读回一条匹配消息，重放原审批 ID 后记录仍只有一条。另测错联系人、拒绝、超时、场景变化和并发。 |
| B · Apple Simulator | 在完整 Xcode 的 iPhone Simulator 运行自有 SwiftUI 测试 App 与 XCUITest。私信场景按稳定 ID 检查联系人，打开聊天、填稿、点击 Send 并读回；信息流场景撰写、发布并读回。保留 Xcode、设备型号、运行时版本和 `.xcresult`。 |
| C · MCP 驱动测试 App | 步骤 0a 核验 Simulator 与夹具范围，验证超时和当次观察结果。步骤 0b 保持提交路径禁用，在 Codex 中按稳定 ID 定位合成联系人，回读完整草稿并确认记录未新增。步骤 2 单独验收独立审批与持久化防重。未批准和绕行路径均无法提交，批准后回读一条匹配记录，过期及重放被拒绝。 |
| D · Hark 联调 | 可先用 Mock 验证 Hark → SSH → Codex → MCP 连通性。步骤 2 通过后再验收完整合成流程，核对审批、结果回读和中断重连后的防重。提交回执丢失时，结果仍无法核实就暂停。 |
| E · iOS 27 真机 | G3a 取得用户另行授权后开始真机只读取证。G3b 要求 G2 已通过、只读证据齐备、审批已外置，并取得单独的写入授权，才在自有 App 上验证受控写入。真实第三方 App 逐能力另行验证，端侧独立运行由 G4 单独验收。 |

进入外部设备执行阶段前，为任务设置时限、动作和重试预算，并让审批权限独立于 Agent。发送结果不明时先回读，仍无法确认时暂停。金融和支付应用保持禁用。各阶段的最小试错、决策门与排期见 [实现计划](implementation-plan.md)，已运行的测试与剩余条件见 [测试报告](test-report.md)。
