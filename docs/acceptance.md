# 产品目标与分阶段验收

用户希望在 Hark 用一句自然语言指令完成 iPhone 上的受控任务。首期以 iPhone 和 iOS 27 为目标设备，以 Codex 作为主要开发与 Agent 工具入口。第一个目标任务是打开微信、唯一定位测试联系人、拟稿、由用户独立批准、执行一次、回读验证。日常开发由 Codex 执行，用户保留发送审批和真机测试决定。

PhoneBridge 使用原创实现与可替换的执行器。Codex 及其他 stdio MCP 客户端可作为 Agent，DeepSeek API 为可选上层模型。长期目标是减少对常驻电脑或云主机的依赖，具体部署取决于 iOS 与目标 App 提供的能力。[架构](architecture.md) · [iOS 可行性](ios-feasibility.md)

| 阶段 | 验收判据 |
| --- | --- |
| A · Python Mock | 启动 MCP 子进程，发现工具，用固定测试联系人完成拟稿。审批前记录增量为零。独立 CLI 批准后执行并读回一条匹配消息，重放原审批 ID 后记录仍只有一条。另测错联系人、拒绝、超时、场景变化和并发。 |
| B · Apple Simulator | 在完整 Xcode 的 iPhone Simulator 运行自有 SwiftUI 测试 App 与 XCUITest。按稳定 ID 检查联系人，打开聊天、填稿、点击 Send 并读回，保留 Xcode、设备型号、运行时版本和 `.xcresult`。 |
| C · MCP 驱动测试 App | 让同一 MCP 会话实际观察并操作官方 Simulator 上的自有 App，从独立审批到回读完成全链路。现有 `simctl` 适配器覆盖状态、截图与夹具启动，实时 UI 通道待实现。 |
| D · Hark 联调 | 从 Hark 经 SSH 启动 Codex，调用当前 MCP 工具完成上述模拟任务，在 Hark 看见执行与核验结果。单独检验失败、SSH 中断与重连。 |
| E · iOS 27 真机 | 用户另行决定进入真机测试后，核对设备、系统与经授权的执行接口。从只读测试和自有 App 开始，分别记录第三方微信、权限、数据处理与本机运行的可行范围。 |

进入外部设备执行阶段前，为任务设置时限、动作和重试预算，并让审批权限独立于 Agent。发送结果不明时先回读，仍无法确认时暂停。金融和支付应用保持禁用。已运行的测试与剩余条件见 [测试报告](test-report.md)。
