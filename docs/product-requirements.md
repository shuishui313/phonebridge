# PhoneBridge 产品需求

2026-11-10 更新。本文记录产品形态决策，技术边界见 [iOS 可行性](ios-feasibility.md)，安全约束见 [安全边界](security.md)。

## 产品定位

PhoneBridge 是通用的手机操作能力产品，**同一核心，两种产品形态**：

| 形态 | 用户 | 使用方式 |
| --- | --- | --- |
| 接入形态 · PhoneBridge MCP | 已有 AI Agent App 的用户（Hark、ChatGPT、WorkBuddy 及任意 MCP 兼容客户端） | 在 Agent App 里注册 PhoneBridge 后，直接用自然语言下达手机任务；PhoneBridge 作为被接入的能力提供方 |
| 独立形态 · PhoneBridge App | 不使用其他 Agent 的用户 | 独立 App 自带对话入口和模型配置（DeepSeek API 或其他兼容模型），无需安装任何第三方 Agent 即可完成同样的手机任务 |

两种形态共享同一套核心：任务执行循环（观察 → 规划 → 操作 → 验证）、独立审批、安全策略、设备驱动与审计。**差异化只在接入壳，不在核心逻辑。**

## 架构含义

```text
外部 Agent App（Hark / ChatGPT / 其他）      独立 App 用户
        │ MCP（stdio / 远程 HTTPS）                │ App 内对话 UI
        ▼                                          ▼
┌─────────────────────────────────────────────────────┐
│ PhoneBridge 核心：任务引擎 · 审批 · 策略 · 验证 · 审计 │
└─────────────────────────────────────────────────────┘
        │
        ▼
   设备驱动（Mock / Simulator / Xcode MCP / 未来真机）
```

由此产生的工程约束：

1. **核心不得依赖特定 Agent。** 任务状态、审批、验证逻辑放在核心层；Codex、Hark 或任何模型的特定行为只允许出现在接入壳。
2. **接入壳要薄。** MCP stdio 适配器只做协议转换。核心能力以稳定的内部 API 暴露，独立 App 的对话 UI 未来复用同一 API，不复制逻辑。
3. **预留两种 MCP 传输。** stdio 服务面向本机 Agent（Codex、Hark 经 SSH）；ChatGPT 一类云端客户端需要远程 MCP（HTTPS + 鉴权），作为独立传输适配器后续提供，不改动核心。
4. **双通道设备能力不变。** 意图通道（App Intents / 快捷指令）与设备接管通道的划分对两种产品形态一致生效，审批规则一致。

## 阶段顺序

1. 接入形态先行：MCP + Simulator 闭环，验证核心与审批（当前阶段）。
2. 真机通道在用户另行授权后验证，两种形态共用验证结论。
3. 独立 App 形态在核心 API 稳定后启动；其对话与模型配置复用核心，不提前开发。

## 不做的事

- 不做聊天或社交 App 本身，不做模型训练。
- 不为某一 Agent 定制核心逻辑。
- 不在文档中记录其他同类项目名称；调研结论匿名化沉淀。
